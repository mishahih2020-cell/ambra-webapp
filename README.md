# Gорчит Shop — Telegram WebApp

Рабочее веб-приложение магазина табака и кальянной продукции. Дизайн — светлая
бело-красная тема (реализована по пиксельной спецификации `HOOKAH SHOP —
Pixel-level UI specification + Claude Code prompt`: токены, типографика,
компоненты, состав экранов).

Никакой сборки не требуется: чистые HTML/CSS/JS, один SPA на хэш-роутинге.

## Как запустить локально

```
node serve.js
```

Откройте http://localhost:8123 в браузере (в мобильном режиме DevTools для проверки на телефонном экране).

## Структура

```
index.html        — точка входа, подключает Telegram WebApp SDK
css/style.css      — дизайн-система (токены, компоненты, экраны)
js/data.js          — каталог, заказы, промокоды (моковые данные — заменить на API)
js/services.js      — мок-слой бизнес-логики (сейчас только WheelService) —
                       единственное место, куда переносить реальные запросы к бэкенду
js/app.js           — роутинг, состояние (корзина/избранное), рендер всех экранов
serve.js            — локальный сервер для разработки (не нужен в проде)
```

## Модель работы: самовывоз, без онлайн-оплаты

Магазин не занимается доставкой и не принимает оплату онлайн. Приложение —
это витрина + «отложить товар»: пользователь собирает корзину и жмёт «Отложить
товар», в ответ получает бронь (номер, адрес и часы магазина, срок хранения —
`js/data.js → STORE_INFO`), забирает и оплачивает товар на месте. Поэтому в
Checkout нет выбора способа доставки/оплаты — только сводка, списание бонусов/
промокода и подтверждение «заберу и оплачу на месте». История заказов
использует статусы «Отложен» / «Забран» / «Отменён» вместо доставки.

## Управление товарами (для владельца магазина)

Профиль → значок настроек (или пункт «Настройки») → «Управление товарами».
Прямо в приложении можно:
- добавить новый товар (название, бренд, категория, цена, старая цена, бейдж,
  наличие, объёмы, вкус, крепость, страна, описание, фото — по ссылке или
  загрузкой файла до 2 МБ, конвертируется в data URL);
- отредактировать любой существующий товар;
- удалить товар (с подтверждением, автоматически убирается из корзины и избранного);
- сбросить всё к заводским настройкам.

Изменения сохраняются в `localStorage` браузера (`hks_products_override`) и
переживают перезагрузку страницы — но это **на устройстве**, не в общей базе:
у другого посетителя (или в другом браузере) будет видна заводская версия
каталога, пока не подключён настоящий бэкенд. `js/data.js → saveProductOverrides`
— единственное место, которое нужно заменить на реальный API-запрос.

Чтобы перенести правки с одного устройства на всех — на экране «Товары» есть
кнопка «Экспортировать изменения»: она копирует текущий список товаров (JSON)
в буфер обмена. Этот текст можно переслать разработчику, чтобы он прописал
эти данные в `js/data.js` как значения по умолчанию для всех — либо, когда
понадобится, подключить общую базу (Firebase/Supabase), чтобы это происходило
само.

**Доступ защищён PIN-кодом** (только на этом устройстве, это не настоящая
авторизация — просто барьер от случайного/любопытного визита, т.к. экран
открыт всем без сервера и логина). При первом входе приложение попросит
задать свой PIN; дальше он не спрашивается повторно в рамках одного запуска
приложения, но запрашивается заново после полной перезагрузки. PIN можно
сменить или сбросить прямо на экране «Товары».

## Дизайн-токены

Белый/красный, по спецификации: `--bg #FFFFFF`, `--surface #F7F7F7`,
`--primary #F52B32`, `--text #15171A` и т.д. — см. `css/style.css → :root`.
Шрифт — Inter. Радиусы: карточка 12px, крупный 16px, кнопка/поле 10px, чип 999px.
CTA высотой 48px. Красный используется только как акцент (кнопки, бейджи, активные
состояния) — не как фон интерфейса.

## Экраны

Онбординг (18+) → Главная → Каталог (все товары, чипы категорий, сортировка,
фильтры) → Категория (бренд-чипы конкретной категории) → Поиск → Карточка товара
(с блоком «Вам может понравиться» и состоянием «нет в наличии») → Корзина →
Оформление заказа (с чекбоксом согласия) → Подтверждение заказа → Профиль →
Личные данные → Адреса → Мои заказы (с вкладками по статусу) → Детали заказа →
Акции и бонусы → Уведомления → Избранное (с вкладками по категориям) →
Колесо фортуны (результат — bottom sheet, правила — отдельная шторка) →
Реферальная программа → Поддержка → О магазине.

Нижняя навигация — ровно 5 пунктов: Главная / Каталог / Избранное / Корзина / Профиль.

## Фильтры и сортировка

Bottom sheet с реальными `<input type="range">` для цены (min/max), чекбоксами
для бренда/вкуса (множественный выбор) и чипами для крепости, переключатель
«Только в наличии» — всё применяется к списку товаров вживую
(`js/app.js → applyFilters`). Отдельная шторка сортировки (популярность / цена /
рейтинг / новинки). Фильтры сохраняются при навигации между каталогом и
категориями в рамках сессии.

## Лояльность и кешбэк

Три уровня (Silver / Gold / Platinum), кешбэк начисляется бонусами на каждый оплаченный заказ
по проценту текущего уровня, уровень растёт по накопленной сумме покупок (`js/data.js → TIERS`).
Бонусы можно списать при оформлении заказа (до 30% от суммы товаров). Карточка лояльности
с декоративным QR — в Профиле, сворачивается.

## Реферальная программа

Каждому пользователю генерируется персональный код (`GOR-XXXXXX`) и ссылка вида
`?ref=КОД`. Экран «Пригласить друзей» — кнопки «Поделиться» (через Telegram) и «Скопировать
ссылку». Начисление бонусов за приглашённых сейчас на стороне бэкенда не реализовано
(список приглашений в `js/data.js → REFERRALS` — заглушка для демонстрации UI).

## Колесо фортуны

Вероятность приза и списание попытки считает `WheelService.spin()` (`js/services.js`) —
Promise с сетевой задержкой, а не прямой `Math.random()` в обработчике клика, чтобы
при подключении бэкенда поменять нужно было только тело этой функции. Двойной тап
во время прокрутки игнорируется (сервис переиспользует тот же promise, кнопка
дизейблится). 1 бесплатная попытка в день + 1 попытка за оформленный заказ.
Результат показывается в bottom sheet (а не баннером на странице), правила — в
отдельной шторке по иконке (i). Учитывается `prefers-reduced-motion` — при
включённой настройке прокрутка короче и без лишних оборотов. Доступ — через
экран «Акции и бонусы» в профиле.

## Состояние и данные

Корзина, избранное, бонусный баланс, промокоды и прокрутки колеса хранятся в `localStorage`
браузера пользователя. Каталог, заказы, промокоды, уровни лояльности и призы колеса — в
`js/data.js`; при подключении бэкенда замените константы там на реальные запросы к API
(структура объектов уже соответствует тому, что использует рендер).

## Telegram WebApp

Подключён официальный SDK (`telegram-web-app.js`). При запуске внутри Telegram:
- автоматически разворачивается на весь экран (`expand()`);
- цвет шапки/фона подстраивается под светлую тему приложения;
- кнопка «Назад» в Telegram используется для навигации между вложенными экранами;
- лёгкая вибрация (haptics) на ключевых действиях (добавление в корзину, оформление заказа).

Вне Telegram (обычный браузер) всё работает так же — SDK просто не активируется.

## Деплой

Разместите содержимое папки на любом статическом хостинге (Vercel, Netlify, GitHub Pages, свой сервер)
и укажите публичный HTTPS-адрес в настройках Mini App у @BotFather.

Сейчас сайт раздаётся через GitHub Pages прямо из ветки `main` репозитория
`mishahih2020-cell/ambra-webapp` — она пересобирается автоматически при каждом
`git push`, обычно за 1–3 минуты, без ручных действий.

**Важно при любом деплое, меняющем css/js/фото** — бампнуть `ASSET_V` в
`index.html` (строка `window.ASSET_V = '...'`, плюс `?v=...` у `css/style.css`
и трёх `<script src>`). Без этого Telegram WebView может продолжать показывать
старую закэшированную версию на уже открывавших приложение устройствах, даже
когда на сервере уже лежат новые файлы — сервер тут ни при чём, кэш живёт на
стороне клиента. Пути к фото в `js/data.js` (`TPHOTO`/`RPHOTO`) берут версию
автоматически из `window.ASSET_V`, их бампать отдельно не нужно.

Если после деплоя с новой версией устройство всё равно показывает старое —
это уже не история с сервером: нужно полностью закрыть Telegram (смахнуть из
списка недавних приложений, не просто выйти из Mini App) и открыть заново —
это принудительно заставляет Telegram перезапросить страницу.
